# Ninth Slate — Delivery Standard

Every completed engineering task should aim to include:

## 1. What changed
Short plain-language summary.

## 2. Why
Root cause or implementation reason.

## 3. Files / systems affected
Relevant surfaces only.

## 4. Verification
What was tested.

## 5. Known limitations
Anything not solved or outside scope.

## 6. Next steps
Only when useful.

## 7. Version control
Clear commit history where repository access exists.

## Principle
A task is not complete merely because the code was written. The result must be verifiable.
