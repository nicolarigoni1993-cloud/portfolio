# Ninth Slate — Commercial Services

Status: internal commercial framework. Pricing intentionally not fixed yet.

## Positioning

Ninth Slate should not sell vague "digital solutions". It should sell clearly scoped engineering outcomes.

Until a formal business structure exists, contracts may still be handled personally by Nicola Rigoni while Ninth Slate acts as the studio/product brand.

---

## 1. Bug Fix Sprint

### Best for
Existing web applications with a reproducible bug, broken workflow, responsive issue, auth problem, API failure or database-side defect.

### Typical scope
- Reproduce the issue
- Inspect affected frontend/backend/data flow
- Identify root cause
- Implement focused fix
- Test affected workflow
- Run likely regression checks
- Document the change

### Technologies
React, TypeScript, JavaScript, Python, FastAPI, Supabase, PostgreSQL, REST APIs.

### Sales message
"Give us the broken workflow and expected behavior. We trace the issue, fix the smallest reliable surface, and verify the result."

---

## 2. Feature Sprint

### Best for
A product that already works but needs one new capability.

### Typical scope
- Requirement clarification
- Existing-codebase review
- Data/API impact analysis
- Feature implementation
- Responsive behavior
- Regression testing
- Delivery notes

### Good examples
- New dashboard section
- User-specific feature
- New form/workflow
- Role-based access
- Notification flow
- New API integration
- New reporting view

Products that need to connect frontend, backend, database or third-party services.

### Typical scope

- Supabase/PostgreSQL workflows
- Authenticated requests
- Data validation
- Error handling
- User-specific data

## 4. Internal Business Tool

### Best for
Small companies or teams replacing spreadsheets, scattered files or repetitive manual workflows.

### Typical scope
- Workflow mapping
- Dashboard/interface
- Forms
- Structured data
- User roles
- Internal API/backend
- Search/filtering
- Responsive browser access
- Maintenance plan

### Positioning
Practical internal software, not bloated enterprise transformation.

---

## 5. QA & Release Hardening

### Best for
Applications approaching delivery, release or a major update.

### Typical scope
- Functional walkthrough
- Regression checks
- Responsive/mobile QA
- Auth/session checks
- Error-path review
- Release checklist
- Documentation of findings

### Deliverable
Prioritized issue list plus fixes when included in scope.

---

## 6. Security-Minded Application Review

### Best for
Authorized web applications needing review of access control, auth flows, data isolation or common application-security mistakes.

### Scope boundaries
- Authorized environments only
- No credential theft
- No destructive testing
- No unauthorized scanning
- No claims of formal certification unless one actually exists

### Typical focus
- Authentication/session flows
- Authorization/access control
- IDOR-oriented review
- Supabase RLS review
- Sensitive-data exposure
- Security-minded architecture recommendations

---

## 7. AI Workflow Prototype

### Best for
Teams that want to test whether AI actually improves a workflow before committing to a large integration.

### Typical scope
- Use-case definition
- Prompt/workflow design
- RAG or structured context where useful
- Human-in-the-loop boundaries
- Evaluation criteria
- Cost/control considerations
- Prototype UI or backend flow

### Rule
No "AI transformation" sales language. Sell a measurable workflow improvement.

---

## 8. Maintenance & Improvement

### Best for
Existing products needing recurring small fixes, updates and incremental improvements.

### Typical scope
- Bug triage
- Small features
- Dependency updates
- Regression testing
- Responsive fixes
- Data-flow maintenance
- Release support
