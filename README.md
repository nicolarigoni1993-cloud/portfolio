## How I work

I prefer focused, testable changes over unnecessary rewrites.

Typical workflow:

1. Reproduce the issue or define the exact product requirement
2. Inspect the affected code, API, database and user flow
3. Identify the root cause or smallest reliable implementation path
4. Implement the fix or feature
5. Test the affected workflow and likely regressions
6. Verify mobile / responsive behavior when relevant
7. Document the change and keep the repository history understandable

For larger projects I also use staged releases, regression gates, CI checks, rollback-aware workflows and explicit separation between preview, testing and production.
